# Repository Guidelines

## Project Structure & Module Organization
This repository is a single-module Android app named `LightXin`. Main code lives in `app/src/main/java/com/lightxin`, with shared infrastructure under `core/`, navigation in `navigation/`, and product features under `feature/<feature>/data|domain|ui` (for example `feature/login/ui/LoginScreen.kt`). Resources are in `app/src/main/res`.

`codestable/` is this project's own knowledge base, and is worth reading before touching a module: `codestable/architecture/<module>-overview.md` per feature and `codestable/compound/*-decision-*.md` for recorded decisions. `screenshots/` holds UI reference images.

**`docs/`, `prototype/`, and `HAR/` are git-ignored and are not present in this checkout.** `.gitignore` lists `/docs`, `/prototype`, `/HAR` on purpose — they hold private planning notes, UI mockups and packet captures that never reach the remote. Two consequences: cross-references such as `docs/接口分析/跑步接口深度分析报告.md` inside `codestable/` cannot be resolved from files here, and captured protocol details cannot be re-checked locally. Ask the user when you need them, and never reconstruct their contents from memory. Never force-add those paths to a commit.

## Build, Test, and Development Commands
This checkout builds on macOS with the Gradle wrapper (9.3.1) from the repo root. `gradlew` must keep its executable bit — it was copied from Windows and arrives without one (`chmod +x gradlew`).

- `./gradlew :app:assembleDebug`: build the debug APK.
- `./gradlew :app:installDebug`: install the debug build on a connected device/emulator.
- `./gradlew :app:lint`: run Android lint checks.
- `./gradlew :app:testDebugUnitTest`: run local JVM tests for the debug variant only. This is the fast path; the whole suite takes seconds on a warm dependency cache.
- `./gradlew :app:connectedAndroidTest`: run instrumentation tests on a device.

The JDK is **not** pinned to a machine path any more: `gradle/gradle-daemon-jvm.properties` (generated by `./gradlew updateDaemonJvm`) declares `toolchainVersion=25` with per-OS download URLs, so Windows / macOS / CI all resolve the same daemon JVM. Do not reintroduce `org.gradle.java.home` into `gradle.properties` — it overrides the toolchain declaration with an absolute path and breaks the build on every other machine. Kotlin does not support JVM target 25 yet and prints "falling back to Kotlin JVM_24" — that warning is expected, not a failure.

Android Studio's Gradle sync additionally depends on `~/.gradle/init.d/mirror.gradle`; read 项目碎片知识 → 编译与构建 below before debugging any dependency-resolution error.

Open the project in Android Studio when working on Compose previews, resources, or emulator flows.

## Coding Style & Naming Conventions
The project uses Kotlin official code style and 4-space indentation (`.idea/codeStyles/Project.xml`). Follow package-first organization and keep feature code split into `data`, `domain`, and `ui`. Use descriptive suffixes such as `Repository`, `ViewModel`, `Screen`, `Api`, and `Models`. Compose components use PascalCase function names, Kotlin files use PascalCase, and Android/XML resources use `snake_case` such as `network_security_config.xml`.

## Testing Guidelines
JVM tests live in `app/src/test/java/com/lightxin/` and are already in place for the network, aiclass, running, schedule and update modules. Instrumented tests live in `app/src/androidTest/java/com/lightxin/` — one file so far (`core/auth/RememberedLoginStoreInstrumentedTest.kt`), reserved for code that needs a real AndroidKeyStore. New work should add tests alongside the feature being changed — pure functions under `domain/` are the cheapest to cover.

The JVM test stack is JUnit 4 only (`junit:junit:4.13.2`); there is no Mockito or Robolectric. Instrumented tests add nothing beyond `androidx.test.ext:junit` and `androidx.test:runner`. If a class exposes a method whose signature takes an Android type such as `android.location.Location`, unit tests must avoid that method or the test belongs in instrumentation instead. Name files `SomethingTest.kt` or `SomethingInstrumentedTest.kt`. At minimum, run `:app:testDebugUnitTest` (and `lint`) before opening a PR; use `connectedAndroidTest` for camera, navigation, or login flows that depend on Android runtime behavior — but read the data-wipe warning under 项目碎片知识 → 测试 first.

## Commit & Pull Request Guidelines
This checkout **is** a git repository: `origin` is `https://github.com/SDX8/lightxin.git`, branch `main`. History before 2026-10-13 lives only on the remote (this directory was copied without its `.git`), so `git log` here starts from that date — do not assume older commits or files are available locally.

Follow the existing commit convention: concise Chinese task-oriented subjects, often with phase tags, for example `完成Phase9C UI精炼：首页叙事架构 + 我的页精简`. Keep commits focused on one change set. Commit messages must include both a subject line and a body; do not create title-only commits. The body must spell out what changed and what validation was run, preferably as short bullets. PRs should include: what changed, affected screens/modules, commands run, and screenshots or recordings for UI updates. Link related docs or issues when the change is tied to a plan in `codestable/`.
On macOS, pass multi-line messages through a real heredoc (`git commit -m "$(cat <<'EOF' … EOF )"`) or `git commit -F <message-file>`; a literal `\n` inside a quoted argument is committed as text and will not render as a line break.

## Security & Configuration Tips
Do not commit `local.properties`, captured HAR files, tokens, or device-specific data. Keep secrets out of source and route network-related changes through `core/network/` so auth and interceptors stay centralized.

## Hard Constraints
These constraints are non-negotiable. Changing any of them requires consulting the full decision documents linked below.

- **No map SDK** — Location uses native `LocationManager`; coordinate conversion (WGS-84 → GCJ-02 → BD-09) is hand-written in `core/location/CoordinateConverter.kt`. Do not add AMap / Baidu / Tencent map or location SDKs. → `codestable/compound/2026-04-22-decision-no-map-sdk.md`
- **Running data RSA encryption — keys always, values except `runningRoute`** — Field names AND field values are encrypted with `publicKey2` via `RSAUtils.encryptSportData()`; never encrypt only the values. The single exception is `runningRoute`, which must be sent **in plaintext**: it is the only long field (several KB → dozens of concatenated RSA blocks) and the server cannot decrypt that framing, which makes the record invalid ("运动轨迹异常，无效") with no track. Verified empirically on 2026-10-14 — same data, encrypted route = invalid, plaintext route = valid. `publicKey2` (running) and `publicKey` (login) are not interchangeable. → `codestable/compound/2026-10-14-decision-running-route-plaintext.md`
- **API protocol must match original app** — All external requests must match the original app's captured protocol exactly. Field names with typos (e.g., FIF's `couseItemId`) are kept as-is.
- **Check-in multi-header auth** — The check-in API (`fdygl.aiit.edu.cn`) requires 7 identity fields simultaneously; missing any one returns `-100 非法访问`. → `codestable/compound/2026-04-22-decision-checkin-multi-header-auth.md`

### 编译与构建
- macOS 本机可直接构建（2026-10-13 验证：`./gradlew :app:testDebugUnitTest` 61 个用例全绿；`./gradlew :app:assembleDebug` BUILD SUCCESSFUL，产出 `app/build/outputs/apk/debug/app-debug.apk`）。三个仓库之外的前提：
  1. `~/.gradle/init.d/mirror.gradle` —— 用 `beforeSettings` 把阿里云 `gradle-plugin` / `public` / `google` 三个镜像插到仓库列表**最前面**。顺序是关键：Gradle 的 POM 在哪个仓库命中，jar 就固定从哪里下，不会回落；而 Maven Central 对本项目部分 jar 返回 **403**，所以镜像排在 `mavenCentral()` 之后等于没配。这个文件在用户目录下，不入库，新机器要自己复刻一份，否则 Android Studio sync 会报 `Plugin [id: 'com.google.devtools.ksp', ...] was not found`。
  2. `gradlew` 有执行位（从 Windows 拷回来会丢）。
  3. daemon JVM 由 `gradle/gradle-daemon-jvm.properties` 声明（toolchain 25）；本机命中的是 Android Studio 自带 JBR。
- macOS 的系统代理（`scutil --proxy` → `127.0.0.1:7897`）会被 Gradle 的 JVM 继承，而 `curl` 不继承它。出现过「curl 测各镜像都 200、Gradle 却报 `Remote host terminated the handshake`」的误导场面 —— 排查网络类构建失败别只信 curl 的结论。
- 旧条目「WSL 下没有 JDK，gradle 必须用 Windows 终端跑 `gradlew.bat`」是上一工作区（Windows + WSL）的约束，本机不适用。

### 测试
- `:app:testDebugUnitTest` 只跑 debug 变体，是日常入口；`:app:test` 会把 release 变体一起跑。
- 只有 JUnit 4，方法签名里带 `android.location.Location` 之类的 API 在纯 JVM 测试里要绕开（例：`RunningTrackerTest` 只覆盖不需要 Location 的状态机路径）。
- **`:app:connectedDebugAndroidTest` 会先清空被测应用在设备上的数据再跑**（AGP 默认行为，2026-10-14 在模拟器上踩过：登录态、课表缓存、FIF 身份全没了，得重新登录）。别拿还想保持登录状态的设备当仪器化测试机，跑之前先确认丢了登录无所谓。
- 仪器化测试目前只放真正依赖 Android 系统能力的东西（`RememberedLoginStoreInstrumentedTest` 验 AndroidKeyStore 加解密往返）。DataStore 是进程级单例，仪器化测试写的是应用真实偏好文件，测试自己要在 finally 里还原。
